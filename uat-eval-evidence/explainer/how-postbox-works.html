Why, and where it’s decided

Each turn starts with what happened since that agent’s last one, newest first, until 40 items or the next item would pass 16,000 characters. Its own messages are left out, each item is cut at 2,000 characters, and read_conversation reads what was left out. Issue #1: an agent that saw only its @-mention answered confidently about a discussion it never read.

Why, and where it’s decided

Feedback that must be consistent (choices, forms, confirms, reviews) comes from a fixed catalog Postbox renders with its own code; everything else an agent writes runs in a sandbox behind a narrow bridge (principle 1). Apps are sandboxed by a CSP header, so they get an opaque origin and no network; the bridge answers only frames whose origin is null.

Why, and where it’s decided

Every change is a numbered event appended to a JSON Lines log; the state is rebuilt from it. Postbox snapshots every 5,000 events and keeps the last 20,000 in memory for reconnecting browsers (8 and 12 here, so you can see them). A browser sends the last number it has; a server that no longer holds the next one tells it to refetch the whole state.

Why, and where it’s decided

An @-mention wakes an agent; a reply wakes its waker only if it @-mentions it. After 10 agent wakes in a row, or 2 in a row between the same two agents, the next waits for your Allow. Each pair keeps its own count; your writing, Allow or a command resets them all. Only one wake waits at a time: while it does, wakes under the limits still go through, and one that needs a second card is refused and must be sent again.
