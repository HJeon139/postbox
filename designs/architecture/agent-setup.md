# What shapes an agent’s turn

Part of [the architecture](../architecture.md). Everything Postbox passes to a turn, explicitly and in one place: the person’s own setup, with a few overrides.

**Decision** ([#57](https://github.com/HJeon139/postbox/issues/57)). Everything that shapes a turn is passed explicitly, in one place ([`server/adapters/setup.mjs`](../../server/adapters/setup.mjs)), so an agent has the person’s own setup with only the overrides below. These apply to the Claude backends; how the Kiro, Antigravity and Codex backends map them is in [backends.md](../backends.md).

## Setting sources

`--setting-sources user,project,local` (the SDK’s `settingSources`), so an agent has the same skills, slash commands, plugins and permission rules as your terminal. A persona set to Isolated (“Uses your Claude Code setup” off) gets `project,local`: the project’s settings, and the local file where Always allow saves its rules.

## Output style

`--settings '{"outputStyle":"default"}'` (the SDK’s `settings`). The flag layer sits above your user, project and local files, so a style such as Concise can’t fight the agent guide. A real turn confirmed it: with Concise in the folder’s local settings, `init.output_style` read `default`.

## Publishing tools

`--disallowedTools` (the SDK’s `disallowedTools`) removes tools that publish outside Postbox, unless the persona “Can publish outside Postbox”. In a UAT run an agent published its result as a claude.ai artifact, so the work left the conversation. The list is the built-in Artifact, ArtifactComments, ArtifactData and PushNotification, plus connector tools matched by verb (deny rules take globs in the tool name). Outward verbs such as `mcp__*__send_*` match any server; `create` and `upload` match only claude.ai connectors (`mcp__claude_ai_*__create_*`), so a local server’s `create_directory` or `git_create_branch` stays usable: never denied, though it asks first as a write (below). It was built from a real `init` event’s `tools`, and a second real turn confirmed Claude Code removed exactly those. Read-only connector tools stay, and no rule may match Postbox’s own tools, since deny beats allow. A real turn with your connectors and plugin servers loading confirmed it again ([#59](https://github.com/HJeon139/postbox/issues/59)).

## Writes outside Postbox

**Harness first** (the person’s decision, 7 November 2026). In Auto, Postbox adds none of these rules, so the harness decides and a card comes only when it asks; the person’s own ask rules still go, and the rest of this item applies to Ask me and Accept edits. The person had approved about 258 cards and confirms in a day, about 165 of them repeating a kind they’d already allowed, because these rules sent every push and gh write, and any chain holding one, to a card on top of Auto (`writeRules` in [`server/adapters/setup.mjs`](../../server/adapters/setup.mjs), which the CLI, the SDK and a host’s turn all build from). Ask me and Accept edits add ask rules (`permissions.ask` in the settings overlay, `WRITE_TOOLS`) for tools named for writing (`create`, `update`, `write`, `delete` and the rest, at `_` or `-` and in camelCase) and for `gh` commands that file or change issues, pull requests and releases, and `git push`, including one behind git’s options before the subcommand (`git -C dir push`) and any git run with config set on its command line (`git -c …`, which can make another word a push, [#830](https://github.com/HJeon139/postbox/issues/830)). Without the push rule, auto mode’s classifier judged each push, and refused one the person had just approved ([#296](https://github.com/HJeon139/postbox/issues/296)). Claude Code then asks Postbox before each, and the permission card shows the call’s draft as Markdown before anything exists outside. Ask beats allow, so Postbox lets a call through itself when the person settled it: an allow rule that names that tool (what Always allow on the card saves; a whole server allowed for its reads doesn’t count), or a publishing tool for a persona that may publish ([`server/write-guard.mjs`](../../server/write-guard.mjs), [#112](https://github.com/HJeon139/postbox/issues/112)). For a persona in Auto, a call these rules catch can also run when the person asked for it, unless one of their own ask rules covers it too, or it’s a host’s: the turn began with them confirming a confirm that shows the exact command in code, or their typed message asks for it, as one Haiku call quotes. Postbox checks the quote is two or more whole words they typed, with no “don’t”, “never” or “not” in its sentence, nor a “no” or “without” before a word of the call (“no push”, though “no draft” is fine), and shares a word with the call’s own words, not a title or a body the agent wrote; a block’s words are the agent’s and never quoted. An allow-list in code decides first what a request may ever cover: `gh` creates, comments and edits on the project’s repository or one the person named and on items this conversation made or they named, commands that only read files in the project (no hidden file, glob or link that leads out), and MCP tools named to create or edit, with only the fields that allows (text, a PR’s branches, a repository or an item the person named). A title, a body or a message is text: no `$variable` or command in it, except the quoted here-document Claude Code writes a body with. Names are compared whole, so `eon139/postbox` isn’t `hjeon139/postbox`. Never a git command as the agent wrote it: a push or a commit does what the repository’s config, hooks and remotes say, which the agent can change with calls Postbox never sees. A lone `git push` the person asked for is judged by its consequence instead, and Postbox makes it itself ([`server/push-on-request.mjs`](../../server/push-on-request.mjs)): commit <sha> lands on branch <b> of the repository the person set on the project in Settings, never one read from `.git/config`, with no force. Postbox reads the branch and the commit from the files in `.git` without running git there, and pushes from an empty bare repository of its own that borrows the agent’s objects (`objects/info/alternates`), with no system, global or local config, no hooks, only `PATH` and the SSH agent from the environment, and the person’s `gh auth git-credential` as the credential helper, so it never sees a token. A branch the person didn’t name must be the one checked out, and never the remote’s default; which branch is checked out is the agent’s choice, so “push it” covers whatever branch the agent is on, other than the default. The commit goes with the commits before it that the remote doesn’t have, and the sentence says so. Every git call Postbox makes names its own repository (`GIT_DIR`, with `GIT_CEILING_DIRECTORIES`), so a `.git` an agent planted in the temp folder is never read, and ssh runs with no config file (`ssh -F /dev/null`). The files in `.git` are read only as regular files of a few kilobytes, in the agent’s folder itself, never above it. It reads the branch back with `git ls-remote`, the agent’s own push answers no with what landed where, the line says so, and the work ledger records the push. When Postbox’s push fails, or no repository is set, the push asks on a card. Five calls a turn, a line with the whole call and Stop, and a card whenever anything fails ([`server/write-intent.mjs`](../../server/write-intent.mjs), [`server/request-floor.mjs`](../../server/request-floor.mjs), [#296](https://github.com/HJeon139/postbox/issues/296)). A command is read part by part, as for a chained command (below): a `gh` write in a command substitution or after a heredoc counts, one in a heredoc’s body is data unless a shell is on its line (`bash <<EOF`, `cat <<EOF | bash`), and the command passes only when each of its writes is settled. Where the reading can’t be sure, such as after a quote that never ends, the rest counts as commands too. No rule may match Postbox’s own tools.

- **Local servers ask too, in Ask me and Accept edits.** A local server can write to a remote service (a doc tool’s server runs on this computer), and Postbox can’t tell which, so the rules don’t skip them. The cost: local write tools, such as a filesystem server’s `write_file`, a git server’s `git_create_branch` or a memory server’s `add_observations`, show one card each until the person presses Always allow on that tool. The user chose this over leaving local servers out (23 October 2026).

## Your MCP servers

From [#59](https://github.com/HJeon139/postbox/issues/59). They load as in your terminal, claude.ai connectors and plugin servers included. Postbox adds its own with `--mcp-config` (the SDK’s `mcpServers`), always named `postbox`. An Isolated persona gets `--strict-mcp-config` (`strictMcpConfig`), so only Postbox’s loads. A persona can turn any of yours off: they go in the settings overlay’s `deniedMcpServers`, the denylist Claude Code merges from every source. A real turn confirmed a turned-off server leaves the `init`’s `mcp_servers`, with its tools. The persona sheet lists the servers found in your config (user, project and local scopes, names only) and the ones the last `init` reported, with that init’s status.

## Postbox’s own skills

From [#206](https://github.com/HJeon139/postbox/issues/206). Every agent on this computer loads Postbox’s skills, Isolated or not, as it loads Postbox’s MCP server. A Claude agent loads the plugin itself: `--plugin-dir` (the SDK’s `plugins`) names [`agent-plugin`](../../agent-plugin). The other backends don’t read Claude Code plugins, so each gets its `skills` folder in what Postbox already writes for a turn: Antigravity a copy in the turn’s workspace plugin, Kiro a `skill://` resource in the turn’s agent file, and Codex an extra skills root on the turn’s app-server (`skills/extraRoots/set`), held in memory. Nothing more is written into your project or your own setup ([`server/adapters/agent-plugin.mjs`](../../server/adapters/agent-plugin.mjs)). Kiro names the skill `visual-explainer`; the others, `postbox:visual-explainer`. It holds one skill, `postbox:visual-explainer`, which loads when you ask how something works or what your data shows, and picks a form for the picture from the content’s shape. Its starter briefs stay in [`designs/skills/visual-explainer`](../skills/visual-explainer/README.md), since they hold each test’s intended idea. A turn on a host doesn’t get it, since the folder is on this computer. `POSTBOX_AGENT_SKILLS=off` leaves it out for every agent, for a UAT baseline (`- skills: off`). A deny rule such as `Skill(postbox:visual-explainer)` in your settings stops the skill from running, but its description still reaches the agent: a real turn’s `init` still listed it.

## Each persona’s skills

From [#207](https://github.com/HJeon139/postbox/issues/207). The persona sheet lists the skills its agent loads, each ticked unless the persona turns it off (`skillsOff`), from its next turn ([`server/adapters/skill-config.mjs`](../../server/adapters/skill-config.mjs), `GET /api/skills`). The list holds Postbox’s, yours (`~/.claude/skills`, or `CLAUDE_CONFIG_DIR`’s) and the project’s (`.claude/skills`) read from disk, and your plugins’ from the last turn’s `/` menu, since no file says which plugins are on. Claude Code’s built-in skills aren’t listed. An Isolated persona’s list leaves out yours and your plugins’, which it doesn’t load. How each is turned off, from [Claude Code’s skills docs](https://code.claude.com/docs/en/skills): every one gets a `Skill(<name>)` deny rule, which refuses the call; a user or project skill is also hidden with `skillOverrides: { <name>: "off" }` in the settings overlay; a plugin’s skill can’t be hidden that way, so the agent still sees it, and its row says so; and Postbox’s plugin is left out of a turn that turns off all of its skills. The list shows only for a backend whose `capabilities.skills` says it loads them, and not for a persona on a host, which has its own. Antigravity, Kiro and Codex say `'postbox'`: Postbox gives them only its own skills, so only those are listed, and each leaves out the ones the persona turned off (`postboxSkillsOn`): Antigravity’s plugin copies only those, and Kiro’s agent file names only those. Codex’s extra skills root is a whole folder, so a persona that turns any of Postbox’s skills off gets none of them there. Not checked with a real turn: the CLI on this computer was signed out on 7 November 2026, so the deny rule and `skillOverrides` rest on the docs.

## Hooks off where Postbox’s write asks apply

From [#817](https://github.com/HJeon139/postbox/issues/817), [#806](https://github.com/HJeon139/postbox/issues/806). Ask me and Accept edits add `disableAllHooks: true` to the settings overlay (`--settings`, the SDK’s `settings`, and a host’s turn, all from `settingsFor` in [`server/adapters/setup.mjs`](../../server/adapters/setup.mjs)). Those are the modes that get Postbox’s ask rules for writes outside it (above), and both read one definition, `asksForWrites` in [`shared/hook-modes.mjs`](../../shared/hook-modes.mjs), so they can’t drift apart. A hook or a Claude Code mod that approves a call in its `PreToolUse` check skipped those ask rules and the permission card, as a full turn confirmed (#806). The flag layer sits above your user, project and local settings, so a `disableAllHooks: false` there doesn’t undo it ([Claude Code settings](https://code.claude.com/docs/en/settings)). What it turns off, in those two modes and for Postbox’s turns only (your terminal is unchanged): hooks from your settings files and from plugins, and your custom status line, which the same key turns off. In Auto, in an unset or unknown mode (which runs as Auto) and in Run everything, your hooks run, as in your terminal. The person decided this on 8 November 2026, under harness first ([#961](https://github.com/HJeon139/postbox/issues/961), “Writes outside Postbox”, above) and principle 6 of [intent.md](../intent.md) (“You stay in charge of your agents”: the harness decides in the mode you set, and Postbox adds no gate on top): in Auto Postbox adds no write ask rules of its own, so turning hooks off there mostly turned off your own protective hooks. Auto still shows a card when the harness itself asks, and for your ask rules and the conversation’s, and a hook that approves a call skips those too (the risk below). Run everything keeps them, since there they may be the only check left. #806 found a risk this leaves too: a mod’s `$.session.send` messages your other sessions past the `SendMessage` deny, which doesn’t reach a mod’s API call, and outside Postbox’s record.

- **Hooks in a skill’s or subagent’s frontmatter are off too, in the same modes** ([#871](https://github.com/HJeon139/postbox/issues/871), [#920](https://github.com/HJeon139/postbox/issues/920)). Claude Code registers them for the session when the skill or subagent runs; a subagent’s only when the project folder is one it trusts (`hasTrustDialogAccepted` in `~/.claude.json`), which a person’s own projects usually are. Real turns on Claude Code 2.1.318 (CLI) and 2.1.306 (the Agent SDK’s) showed an approving frontmatter hook doesn’t run in Auto, when Auto still turned hooks off, and runs in Run everything, for both kinds (`tests/integration/claude-code-frontmatter-hooks-e2e.test.mjs`, opt-in). Since #806 that test asks in Ask me, and hasn’t been run there yet.
- **Hooks your organization manages always run.** Hooks in managed settings aren’t turned off by `disableAllHooks` from a lower layer ([Claude Code hooks](https://code.claude.com/docs/en/hooks)), so one that approves a call still skips the card in Ask me and Accept edits. Postbox can’t change managed settings, and that is the risk left. The person accepted it on 6 November 2026, on condition that the permissions panel names each `PreToolUse` hook in the settings files the agent reads (your user settings only when it uses your setup, since an Isolated persona doesn’t load them), says in which modes they run in Postbox’s turns (since #806: they run in Auto and Run everything, and are off in Ask me and Accept edits), and says that managed hooks always run ([`server/permission-hooks.mjs`](../../server/permission-hooks.mjs)). Since [#871](https://github.com/HJeon139/postbox/issues/871) it names each `PermissionRequest` hook too, the other event whose hook can approve a call or change its input (`PermissionRequestHookSpecificOutput` in the Agent SDK’s `sdk.d.ts`), with each hook’s event, and says it can’t list plugins’ hooks: Claude Code documents where a plugin is turned on (`enabledPlugins`) but not where its hooks are kept. The person chose not to turn hooks into deny rules instead. Revisit when Claude Code lets ask rules hold against a hook’s allow, or when Postbox needs a hook of its own in these turns: the snapshot before each command that #240 plans would be turned off too, in Ask me and Accept edits.
- **In Auto, a hook that approves a call skips your own ask rules too.** Your hooks run there, so one of yours that approves a call also skips your own ask rules and the conversation’s rules ([#66](https://github.com/HJeon139/postbox/issues/66)), as it would in your terminal (`permissions.md` in Claude Code’s docs, “Precedence among rules, hooks, and mods”). That is a risk the decision of 8 November 2026 leaves: where you need Postbox’s rules to hold against a hook of yours, Ask me and Accept edits turn hooks off.
- **A turn that loaded your hooks keeps its mode rather than turn them off.** A turn started in Auto, in an unset or unknown mode, or in Run everything loaded your hooks when it started. A live switch into Ask me or Accept edits would leave them running where the panel says they don’t, able to approve a call past that mode’s ask rules and card, so it applies from the next turn, or from Stop now, as for a backend that can’t change a running turn ([#371](https://github.com/HJeon139/postbox/issues/371)); the panels say so, with Postbox, not the backend, as the reason, and the hooks section says the running turn still runs them ([#1030](https://github.com/HJeon139/postbox/issues/1030)). A turn started in Run everything keeps it until it ends, since an Agent SDK turn there has no permission callback and no ask rules for writes outside Postbox. A switch from Ask me or Accept edits takes effect now, since that turn’s hooks stay off: into Auto or Run everything, the turn runs without them until it ends, and the panels say they load from its next turn (#1030; `switchesLive` in [`shared/hook-modes.mjs`](../../shared/hook-modes.mjs), which `liveControl` in [`server/adapters/agent-sdk.mjs`](../../server/adapters/agent-sdk.mjs) asks). The Claude Code CLI never changes a running turn’s mode, and a host’s turn runs the CLI.
- **Credentials in a hook’s text are hidden.** The panel’s list goes to the page with `GET /api/permissions`, so values named like a key, token, secret or password, and bearer tokens, become an ellipsis on the server first. It’s best effort: a credential under another name still shows.

## The Tools checklist

From [#5](https://github.com/HJeon139/postbox/issues/5). An unticked tool is a deny rule in `--disallowedTools` (`disallowedTools`): `shell` denies Bash and Monitor, `web.fetch` denies WebFetch, WebSearch and Monitor. A ticked tool is not an allow rule: `--allowedTools Bash` would skip the permission mode’s ask for every command, so ticked only means “not denied”, and the mode still decides. The map lives in `setup.mjs` (`TOOL_RULES`), taken from a real `init`’s `tools`.

## Agents outside Postbox

SendMessage, ListAgents, RemoteTrigger, CronCreate, CronDelete, CronList, ScheduleWakeup and Workflow are denied unless the persona has `agents.outside` (“Message, schedule or start agents outside Postbox”). They bypass the wake cap and the record of who woke whom; `schedule_wake` and `wake_agent` are Postbox’s way. Personas from before the id existed don’t have it, so they’re denied. Monitor is a command (the Tools above decide it), and EnterWorktree stays: it works in a git worktree of the agent’s own folder, which the permission mode governs.

## Model and effort

From [#60](https://github.com/HJeon139/postbox/issues/60). Both are always passed (`--model` and `--effort`, the SDK’s `model` and `effort`), so your own `effortLevel` doesn’t decide them. A persona’s effort is one of low, medium, high, xhigh and max, and defaults to medium, which is what Claude Code uses for `claude-opus-5-5` when none is given (a real turn printed it from `CLAUDE_EFFORT`). Like the model, it follows the persona from the agent’s next turn. The stream reports the model in `init` and in each assistant message, but not the effort, so a session keeps the model that answered its last turn (`lastModel`) and the effort Postbox started it with (`lastEffort`).

Like the permission mode and the tools, these settings follow the persona from the agent’s next turn.
