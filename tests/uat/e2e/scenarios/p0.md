# P0 hotfixes: long messages between agents, a draft revised under review, and stopping agents

- persona: An engineering lead getting a small open-source Python library ready for its 2.0 release. Knows the code well, wants two agents to work the release checklist out between them, and signs off on the final list before anyone acts on it. Busy, writes short messages, and changes their mind now and then.
- agents: researcher, critic
- project: Release 2.0
- conversation: The 2.0 release checklist

Both agents run on Claude Code. This run puts a room in the conditions of the four P0 defects fixed before merging to main (#108, #123, #125, #126), so watch for them as the person would see them: an agent that gets only the start of a long message another agent sent it; two copies of one draft asking at once; an answer to a draft that disappears, or lands on a version you didn’t read; an agent that goes on working after you stop it; and a command an agent left running in the background, when you stop it or send it something new.

## Phase 1: Long lists between the agents

Ask @researcher for a release checklist for 2.0: packaging, deprecations, docs, CI, security and a migration guide, at least 40 items, each with a sentence on why. Ask @critic to go through it and send its full list of fixes straight to @researcher, and @researcher to answer each list with the whole revised checklist straight back to @critic, for three or four rounds, without you in between. Their messages to each other should be long, several thousand characters each. After three wakes in a row, Postbox asks you before the next one: allow it. Then open the side thread between them and check that the agent woken by the wake you allowed got the whole message: ask it for the last item of the list it just received, and compare that with what the sender wrote.

## Phase 2: A draft revised while you answer

Ask @researcher to put the checklist up for your approval, and to write it to `CHECKLIST.md` in the project folder only once you approve it, saying which revision it wrote. Ask @critic to review the same draft and tell @researcher what to change, so @researcher revises it while you’re answering. On the first revision, request changes with comments on two lines. While @researcher is revising after your comments, change your mind about one of them: write the correction and use Send now on it, about 20 seconds into its turn. Approve a later revision only once it reads right. Then ask @researcher which revision it wrote to `CHECKLIST.md`, and to quote its first and last items. You should never see two copies of the draft asking at once, an answer of yours vanish without a reason, or a file written from a revision you didn’t approve.

## Phase 3: Stopping an agent with a command in the background

Ask @researcher to start a background command in the project folder: a shell loop that appends the time to `heartbeat-1.log` every 5 seconds for 3 minutes, using only `sleep` and `echo`, nothing over the network. While it runs, it should check the file every 20 seconds and tell you how many lines it has. About 40 seconds into that turn, press Stop. Postbox should ask whether to stop the background command too: keep it running. Ask @researcher how many lines `heartbeat-1.log` has, twice, a minute apart: it should still be growing, and its step should still show as running. Then do the same with `heartbeat-2.log`, and this time stop it too: the file should stop growing. Last, start `heartbeat-3.log` the same way, and about 30 seconds into the turn, ask @researcher for a one-line status and use Send now on it. Postbox shouldn’t ask about the command, the command should keep running, and @researcher’s reply should know it’s still running.
